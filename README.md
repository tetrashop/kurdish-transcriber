# سامانه هوشمند رونویسی و ترجمه بلادرنگ کردی (Kurdish Real-time Transcriber & Translator)

## چکیده (Abstract)
این مقاله به مستندسازی معماری، توسعه و پیاده‌سازی یک سامانه هوشمند برای پردازش زبان طبیعی (NLP) می‌پردازد که قادر است سیگنال‌های صوتی زبان کردی (سورانی) را به صورت بلادرنگ (Real-time) دریافت، به متن تبدیل کرده و به زبان فارسی ترجمه کند. سامانه با هدف غلبه بر چالش‌های کمبود منابع زبانی کردی، محدودیت‌های ژئوپلیتیکی دسترسی به APIهای هوش مصنوعی، و نیاز به یک مدل تجاری پایدار (SaaS) طراحی شده است. معماری نهایی شامل ترکیبی از مدل‌های تشخیص گفتار (Whisper)، مدل‌های زبانی بزرگ (Gemini)، سیستم حافظه معنایی (RAG) و مکانیزم‌های اعتبارسنجی و مدیریت کاربران است.

## ۱. مقدمه (Introduction)
زبان کردی سورانی از نظر منابع دیجیتال و مدل‌های پردازش زبان طبیعی، یک زبان کم‌منبع (Under-resourced) محسوب می‌شود. مدل‌های استاندارد ترجمه و تشخیص گفتار در مواجهه با الفبای کردی و لهجه‌های محاوره‌ای با چالش جدی مواجه هستند. همچنین، دسترسی به سرویس‌های پیشرو هوش مصنوعی (مانند Google Gemini) از برخی مناطق جغرافیایی (مانند ایران) مسدود است. این پروژه با هدف ایجاد یک راهکار یکپارچه، سریع و اقتصادی، با استفاده از معماری بدون سرور (Serverless) توسعه یافته است.

## ۲. معماری سیستم (System Architecture)
سامانه از یک معماری چهارلایه بهره می‌برد که برای اجرا روی پلتفرم Vercel (پلن رایگان) بهینه‌سازی شده است:

1. **لایه کلاینت (Client-side):** 
   * ضبط صدا با استفاده از `Web Audio API`.
   * الگوریتم تشخیص فعالیت صوتی (VAD) بر اساس آستانه انرژی (RMS) برای جلوگیری از ارسال سکوت و نویز.
   * قطعه‌بندی (Chunking) صدا به بازه‌های ۵ ثانیه‌ای برای کاهش تأخیر (Latency).
   * تبدیل به فرمت WAV (PCM 16-bit) با نرخ نمونه‌برداری 16kHz.
2. **لایه پروکسی و منطق (Vercel Serverless API):**
   * احراز هویت کاربران بر اساس کد دسترسی (Access Code).
   * مدیریت محدودیت نرخ درخواست (Rate Limiting) برای جلوگیری از سوءاستفاده.
   * هدایت درخواست‌ها به سرویس‌دهنده‌های هوش مصنوعی به صورت امن (پنهان‌سازی کلیدها).
3. **لایه پردازش زبان (AI Providers):**
   * **تبدیل گفتار به متن (STT):** استفاده از مدل `Whisper-Large-v3` روی سرویس **Groq** (به دلیل سرعت فوق‌العاده بالا در پردازش).
   * **ترجمه (MT):** استفاده از مدل `Gemini-2.5-Pro` از طریق درگاه واسط **1xAi** (برای عبور از محدودیت‌های جغرافیایی و دسترسی پایدار).
4. **لایه حافظه و داده (Database):**
   * استفاده از **Upstash Redis** به عنوان یک پایگاه داده کلید-مقدار (Key-Value) برای ذخیره اعتبار کاربران و همچنین نگهداری «حافظه ترجمه» (Translation Memory).

## ۳. روش‌شناسی و چالش‌های فنی (Methodology & Technical Challenges)
در طول توسعه این سامانه، چالش‌های متعددی شناسایی و برطرف شدند:

* **توهم‌زنی مدل (Hallucination):** مدل‌های STT در مواجهه با سکوت، کلمات بی‌ربط تولید می‌کردند. راه‌حل: پیاده‌سازی فیلتر VAD قوی و فیلتر کلمات مزاحم (مانند "موسیقی" یا "زیرنویس") در سمت سرور.
* **محدودیت زبان در Groq:** سرویس Groq از کد زبان کردی (`ku`) پشتیبانی نمی‌کند. راه‌حل: تنظیم زبان روی `fa` (فارسی) به دلیل اشتراک الفبا، و استفاده از پرامپت‌های مهندسی‌شده برای ترجمه فونتیک کردی به فارسی.
* **محدودیت جغرافیایی گوگل:** سرویس Gemini از ایران قابل دسترسی نیست. راه‌حل: استفاده از درگاه ایرانی **1xAi** که API سازگار با OpenAI ارائه می‌دهد و نیازی به تغییر لوکیشن سرور یا استفاده از VPN ندارد.
* **مدیریت همزمانی (Concurrency):** ارسال همزمان درخواست‌ها باعث خطاهای شبکه (429 Too Many Requests) می‌شد. راه‌حل: پیاده‌سازی صف مبتنی بر `Promise` در فرانت‌اند و مدیریت خطای 429 در بک‌اند.
* **مدیریت حافظه در Vercel:** سرویس `Vercel KV` بازنشسته شد. راه‌حل: مهاجرت به `Upstash Redis` از طریق Vercel Marketplace.

## ۴. یادگیری فعال و حافظه معنایی (Active Learning & RAG)
برای افزایش دقت ترجمه در لهجه‌های خاص، سیستم به قابلیت **یادگیری فعال (Human-in-the-loop)** مجهز شده است:
1. کاربر می‌تواند ترجمه‌های نادرست را ویرایش کند.
2. متن اصلاح‌شده در پایگاه داده Upstash Redis ذخیره می‌شود.
3. در درخواست‌های بعدی، سرور ۱۰ ترجمه اخیر را به عنوان «راهنما» (Few-Shot Prompting) به مدل Gemini تزریق می‌کند (تکنیک RAG).
4. این چرخه باعث می‌شود مدل به مرور زمان با لحن و واژگان خاص کاربر آشنا شود.

## ۵. مدل کسب‌وکار و مدیریت کاربران (SaaS Architecture)
سامانه به گونه‌ای طراحی شده که به عنوان یک سرویس (SaaS) قابل فروش باشد:
* **کدهای دسترسی (Access Codes):** کاربران برای استفاده از سیستم باید یک کد (مثلاً `USER-1234`) وارد کنند.
* **سیستم اعتبارسنجی (Credits):** هر کاربر دارای اعتبار اولیه است. با هر بار ترجمه موفق، یک واحد از اعتبار او در دیتابیس کسر می‌شود.
* **اسکریپت مدیریت (Admin Script):** مدیر سیستم با استفاده از فایل `admin.js` می‌تواند کد بسازد، اعتبار اضافه کند یا موجودی کاربران را بررسی کند.
* **امنیت:** متغیرهای محیطی (API Keys) هرگز در سمت کلاینت قرار نمی‌گیرند و تمام درخواست‌ها از طریق توابع Serverless پروکسی می‌شوند.

## ۶. تکنولوژی‌های استفاده شده (Tech Stack)
* **فریم‌ورک:** Next.js 14 (App Router)، React 18، TypeScript
* **پردازش صدا:** Web Audio API، ScriptProcessorNode
* **سرور و استقرار:** Vercel (Node.js Runtime، Region: iad1)
* **هوش مصنوعی:** Groq API (Whisper)، 1xAi API (Gemini)
* **پایگاه داده:** Upstash Redis
* **کتابخانه‌ها:** `@upstash/redis`، `openai` (جهت اتصال به درگاه واسط)

## ۷. نصب و استقرار (Installation & Deployment)
برای راه‌اندازی این پروژه، نیاز به تنظیم متغیرهای محیطی زیر در Vercel است:
* `GROQ_API_KEY`: برای سرویس تشخیص گفتار.
* `ONE_X_AI_API_KEY`: برای سرویس ترجمه (از سایت 1xai.ir).
* `UPSTASH_REDIS_REST_URL` و `UPSTASH_REDIS_REST_TOKEN`: برای اتصال به دیتابیس (به صورت خودکار توسط Vercel اضافه می‌شوند).

**اجرای دستورات مدیریتی:**
```bash
# ساخت کاربر جدید با ۱۰۰ اعتبار
node admin.js create USER-1234 100

# شارژ مجدد کاربر
node admin.js add USER-1234 50
```

۸. نتیجه‌گیری (Conclusion)

این سامانه نشان می‌دهد که با ترکیب هوشمندانه مدل‌های متن‌باز و بسته (Whisper و Gemini)، استفاده از درگاه‌های واسط برای عبور از تحریم‌ها، و پیاده‌سازی مکانیزم‌های یادگیری فعال و مدیریت اعتبار، می‌توان یک محصول نرم‌افزاری کاملاً کاربردی، سریع و اقتصادی برای زبان‌های کم‌منبع ارائه داد.
